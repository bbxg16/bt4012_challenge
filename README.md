# Bitcoin Fraud Detection — Final Models

[e1156160.ipynb](e1156160.ipynb) contains the data exploration, model development, chronological validation, final training and inference for both selected Kaggle submissions: **B0** (`graph_lgbm_hgb.csv`) and **Coord3** (`graph_lgbm_hgb_coord3.csv`).

## 1. Place the data

The dataset is **not included in this repository**. Download the original competition data and place these four CSV files in a `data/` folder beside the notebook:

```text
bt4012_challenge/
├── e1156160.ipynb
├── requirements.txt
├── README.md
└── data/
    ├── train.csv
    ├── test.csv
    ├── sample_submission.csv
    └── txs_edgelist.csv
```

Keep the original filenames and contents. The notebook reads relative `data/` paths; no author-specific data location is required. Do not upload the dataset to GitHub.

## 2. Set up Python

Use **Python 3.13** (originally tested with 3.13.0). From the repository root, create an environment and install the pinned dependencies:

```sh
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m ipykernel install --user --name bt4012-final-models --display-name "BT4012 Final Models (Python 3.13)"
```

On Windows, use `py -3.13` instead of `python3.13`, and activate with `.venv\Scripts\activate`. On macOS, if importing LightGBM reports a missing `libomp` library, install the OpenMP runtime with `brew install libomp`.

## 3. Run the notebook

Open this repository folder in VS Code with the Python and Jupyter extensions. Open `e1156160.ipynb`, select **BT4012 Final Models (Python 3.13)** or the newly created `.venv` interpreter, then choose **Restart Kernel and Run All**. Run from the repository root.

No previous models, notebooks or prediction files are required. The first run trains all required models. `USE_CACHE=True` reuses only fingerprint-checked models generated by this notebook; set it to `False` for a complete refit. Exact numerical reproduction requires the pinned environment and unchanged original data.

## 4. Regenerated submissions

The notebook creates both files automatically:

```text
reproducibility/final_two_models/submissions/graph_lgbm_hgb_reproduced.csv
reproducibility/final_two_models/submissions/graph_lgbm_hgb_coord3_reproduced.csv
```

Each contains **15,329 rows**, columns **`index,target`**, the official sample-submission ordering and illicit-class probabilities. These correspond to B0 and Coord3, respectively; the `_reproduced` suffix avoids overwriting original submissions. Models, metrics and integrity checks are saved in the same output directory. No Kaggle upload is performed.

The notebook checks IDs, probability validity and CSV readback. Comparisons against original submission files are optional and skipped when those files are absent. Both submitted probability sets were reproduced within **2.22 × 10⁻¹⁶** in the validated environment. Graph inference uses the documented same-period snapshot assumption and preserves the graph-free fallback for nodes without usable neighbours.
